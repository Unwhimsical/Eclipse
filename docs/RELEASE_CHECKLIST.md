# Eclipse 发版检查单

> 每次发版打 tag 前后照着打勾。违反任何一条都可能导致发版失败。

## 发版前

- [ ] 所有修复已提交到 `main` 分支
- [ ] `main` 分支的构建已全绿（CI 通过）
- [ ] UI 类改动已有真实截图，并在聊天里得到确认
- [ ] 宣传图只在真实截图确认后才更新

## 发版时

- [ ] 使用仓库自带的发布脚本发版：
  ```bash
  tool/release.sh stable --version X.Y.Z --push --yes
  ```
  脚本会自动：重写 changelog → 提交 → 打标签，顺序不会乱。
- [ ] **绝不手动挪 tag**（`git tag -f` / 删除重打都不允许）
- [ ] 无人值守环境必须带 `--yes`（否则报 `/dev/tty` 不存在）

## 发版后（自动盯梢）

- [ ] 打 tag 后自动跟踪这轮构建的全程
- [ ] 构建全绿：在聊天里报一声
- [ ] 构建失败：在聊天里报告挂在哪一步，附失败步骤的日志根因摘要和建议的下一步

## 血泪教训（v0.9.1 三次失败总结）

1. tag 打早了，`changelog.json` 没跟上 → Verify changelog 挂
2. 日志补上了，但测试挂了 → 测试失败
3. 修完测试手动挪标签，但没重生成日志 → changelog 缺最新提交 → 又挂

根因都是：**标签打得太早、之后手动挪标签，`changelog.json` 没跟上**。

正确顺序永远是：修复 → main → 构建绿 → 跑 `release.sh`。
